# Skills — how this repo makes explainers

These are production rules, not optional inspiration. New AI agents should read them before changing story, narration, frames or animation.

## Read order

1. `STORY_STRUCTURE.md` — spine, section chain, five gates, narration lock. **Read first.**
2. `PRODUCTION_ORDER.md` — script → frames → animation; definition of done.
3. `SPATIAL_CONTINUITY.md` — where/what/camera continuity and persistent geography.
4. `BEAT_GRANULARITY.md` — one beat/one move; function before name.
5. `FRAME_COMPOSITION.md` — frozen-frame composition and hierarchy.
6. `DIAGRAM_GRAMMAR.md` — causal diagrams and identity preservation.
7. `EXPLANATION_DESIGN.md` — authored 100vw × 100vh explanation scene rules.
8. `CONTINUITY_SYSTEM.md` — implementation model for persistent actors.
9. `VISUAL_SYSTEM.md` — shared visual language/system constraints.
10. `REFINEMENT_STANDARD.md` — polish threshold and review discipline.
11. `ASSET_LIBRARY.md` — reuse before redrawing.
12. `ENGINE_CAPABILITIES.md` / `INTERACTION_PATTERNS.md` — available implementation tools and interaction patterns.
13. `STRATEGY_LEDGER.md` — evidence/provenance for storytelling strategies.
14. `TEACHING_REFERENCE_LIBRARY.md` and `ncase/` — deeper teaching references.

## Story quality in one screen

A good section should be able to answer all of these:

- What question does the viewer arrive holding?
- What new thing actually happens?
- What does the viewer now know that they did not know before?
- Why could the next question not have been asked earlier?
- What earlier setup does this pay off, or what later payoff does this set up?
- Does the section land the previous answer before introducing new trouble?
- Is the viewer allowed to predict when they have enough schema to reason?
- Is terminology introduced only after its function is understood?

If the section starts and ends on the same question, it is not a story even if every individual beat is polished.

## Hard production principle

**Approved narration outranks implementation.** Never shorten or rewrite locked VO to fit existing visuals. Build the visuals the narration requires.
